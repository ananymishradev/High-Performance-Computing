# Physical Cluster — WSL Host (SRMS1) + Ubuntu Workers

Automated bring-up for a **1 host + N workers** SLURM cluster where:

| Node | OS | You pre-install |
|------|----|-----------------|
| Host (`SRMS1`, user `am_user`) | Ubuntu under **WSL** | Ubuntu + WSL only |
| Workers (`worker1..N`, Ubuntu) | Bare-metal Ubuntu | **only `openssh-server`** |

Everything else — users, packages, SSH, Munge, SLURM, firewall,
**shared storage + shared memory** — is done by the scripts.

## Files

| File | Purpose |
|------|---------|
| `cluster.conf` | Defaults (user, host, workers, share). You can edit it, or just run the host script and **enter IPs when prompted** — answers are saved back here. |
| `setup_host.sh` | Run on `SRMS1`. Configures the host and drives all workers end to end. |
| `setup_worker.sh` | Worker setup. Run automatically by `setup_host.sh`; usable standalone (`WORKER_NAME=worker1 ./setup_worker.sh`). |
| `verify.sh` | Run on the host after setup to test everything. |
| `wsl_port_forward.ps1` | Generated by `setup_host.sh` on WSL+NAT. Run once in Admin PowerShell on Windows. |

## Usage

1. On each worker (fresh Ubuntu), install only SSH and note its LAN IP:

   ```bash
   sudo apt update && sudo apt install -y openssh-server
   hostname -I   # note this IP, e.g. 192.168.1.101
   ```

2. On the host (`am_user@SRMS1`), run:

   ```bash
   ./setup_host.sh
   ```

   It prompts for host IP, each worker `hostname + IP`, the worker's
   **initial SSH user** (the account from Ubuntu install), and the
   shared dir. Then, unattended:

   - installs all host utilities (`slurm-wlm`, `munge`, `nfs`, `openmpi`, …;
     `unfs3` userspace NFS on WSL where kernel `nfsd` is unavailable)
   - creates `am_user` on every worker with the **same UID/GID** as the host
   - sets passwordless SSH (both directions, for MPI/`srun`) + passwordless sudo
   - generates one Munge key, distributes it, syncs clocks
   - exports `/mnt/hpc-shared` from the host, mounts it on every worker
     (NFSv3 — compatible with WSL's `unfs3`), sizes `/dev/shm`
   - probes live hardware (`lscpu`, `free`) on every node, writes +
     validates `slurm.conf`, distributes it, starts `slurmctld`/`slurmd`
     (systemd — or direct-daemon fallback on WSL without systemd)

3. Verify:

   ```bash
   ./verify.sh
   ```

   Checks ping, SSH, Munge (local + cross-node), NFS write/read from
   every node, `/dev/shm`, `sinfo`, `srun` on all workers, and a real
   `sbatch` job that writes into the shared dir.

## WSL networking (important)

WSL2 NAT hides the Linux VM behind Windows, so workers **cannot** reach
the `172.x` WSL-internal IP. Two options:

- **Mirrored networking (recommended):** in `%USERPROFILE%\.wslconfig` put
  `[wsl2] networkingMode=mirrored`, run `wsl --shutdown`, and use the
  normal LAN IP as `HOST_IP`. No port forwarding needed.
- **NAT (default):** `HOST_IP` = the **Windows** LAN IP (`ipconfig` on
  Windows), and run the generated `wsl_port_forward.ps1` in an elevated
  PowerShell (forwards 22, 6817–6819, 111, 2049). Re-run it whenever the
  WSL IP changes (`wsl --shutdown` reboots renumber it).

## Shared storage ("shared memory")

- **Shared filesystem:** `$SHARED_DIR` (default `/mnt/hpc-shared`) is one
  NFS path, identical on every node. Put job scripts, input data, and
  results there — SLURM jobs **must** use paths visible on all nodes.
- **POSIX shared memory:** `/dev/shm` is sized on every node via
  `SHM_SIZE` in `cluster.conf` (`auto` = distro default, ~50% RAM).

## Troubleshooting

```bash
sinfo; scontrol show nodes
sudo tail -f /var/log/slurm/slurmctld.log   # host
sudo tail -f /var/log/slurm/slurmd.log      # any node
munge -n | unmunge                          # must end: Success
df -h /dev/shm; mount | grep hpc-shared
```

| Symptom | Fix |
|---------|-----|
| Node `down` | `sudo scontrol update nodename=worker1 state=resume` |
| Munge `expired`/`invalid` | clocks: `sudo timedatectl set-ntp true` everywhere (WSL syncs from Windows — `wsl --shutdown` if drifted); then re-run host script to redistribute the key |
| Worker can't reach host | wrong `HOST_IP` (use Windows IP on NAT) or missing port-forward `.ps1` |
| NFS mount fails | host firewall/NFS: `sudo exportfs -v` (native) or `pgrep unfsd` (WSL); worker: `sudo mount -a` |
| Job `user not found` | UID mismatch — host script enforces same UID/GID; check `id am_user` on both |
